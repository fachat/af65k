= 65002 Operation Documentation

This page lists all the opcodes of the 65002 with appropriate explanations.


== List of operations


=== Jumps and Returns


* <<BRK,BRK>> - Starts the break routine.
* <<JMP,JMP>> - Jump to new code address
* <<JSR,JSR>> - Jump subroutine - jump to a new code location, save return
				address on stack for RTS
			
* <<RTI,RTI>> - Return from interrupt
* <<RTS,RTS>> - Return from subroutine - read return address from stack
* <<RTU,RTU>> - Return from trap handler.
* <<TRP,TRP>> - Trap into 65k supervisor mode

=== Branches


* <<BCC,BCC>> - Branch on carry clear - take branch when C flag is cleared
			
* <<BCS,BCS>> - Branch on carry set - take branch when C flag is set
* <<BEQ,BEQ>> - Branch on equal - take branch when Z flag is set
* <<BEV,BEV>> - Branch on even
* <<BGES,BGES>> - Branch on signed greater or equal than
* <<BGT,BGT>> - Branch if greater - take branch when C flag is set but Z flag
				is
				clear
			
* <<BGTS,BGTS>> - Branch if greater - take branch when signed greater or equal G
				flag is set but Z flag is clear
			
* <<BLE,BLE>> - Branch if less or equal - take branch when C flag is clear or Z
				flag is set
			
* <<BLES,BLES>> - Branch if less or equal - take branch when signed greater or
				equal flag G is clear or Z flag is set
			
* <<BLTS,BLTS>> - Branch on signed less than
* <<BMI,BMI>> - Branch on minus - take branch when N flag is set
* <<BNE,BNE>> - Branch on not equal - take branch when Z flag is cleared
* <<BOD,BOD>> - Branch on odd
* <<BPL,BPL>> - Branch on plus - take branch when N flag is cleared
* <<BRA,BRA>> - Branch always - branch independent from any flags
* <<BSR,BSR>> - Branch subroutine - similar to JSR, but use relative addressing
				similar to branch opcodes
			
* <<BVC,BVC>> - Branch on overflow clear - take branch when V flag is cleared
			
* <<BVS,BVS>> - Branch on overflow set - take branch when V flag is set

=== Arithmetic & logic


* <<ADC,ADC>> - Add content of memory location to accumulator
* <<ADD,ADD>> - Add content of memory location to accumulator without using
				carry as input
			
* <<ADE,ADE>> - Add value to E register
* <<ADI,ADI>> - Add immediate value to a memory location
* <<ADQ,ADQ>> - Add immediate value to a register
* <<AND,AND>> - Bitwise AND accumulator with content of memory location
* <<ASL,ASL>> - Arithmetic Shift Left - shift accumulator one bit to the left,
				shifting in zero in bit 0
			
* <<ASR,ASR>> - Arithmetic Shift Right - Similar to LSR, but shifts in the sign
				of the value, not zero
			
* <<BCN,BCN>> - Bit Count: counts 1-bits in AC or in given location, stores
				number of 1-bits back in AC
			
* <<BSW,BSW>> - Bit Swap: exchanges bit 0 with bit W-1, bit 1 with bit W-2 and
				so on.
			
* <<CMP,CMP>> - Compare accumulator with content of memory location
* <<CPX,CPX>> - Compare X register with content of memory location
* <<CPY,CPY>> - Compare Y register with content of memory location
* <<CPZ,CPZ>> - Compare Z register with content of memory location
* <<DAD,DAD>> - Decimal adjust of a normal ADC of two BCD numbers.
* <<DAS,DAS>> - Decimal adjust of a normal SBC of two BCD numbers.
* <<DEC,DEC>> - Decrement the content of a memory location by one
* <<DEX,DEX>> - Decrement the content of the X register by one
* <<DEY,DEY>> - Decrement the Y register by one
* <<DEZ,DEZ>> - Decrement Z register
* <<EOR,EOR>> - Bitwise Exclusive-OR accumulator with content of memory
				location
			
* <<EXT,EXT>> - Extend a value in AC from RS to the full size. Setting LE
				defines the type of extension.
			
* <<INC,INC>> - Increment the content of a memory location by one
* <<INV,INV>> - Invert AC, i.e. set AC to the 1s-complement of AC
* <<INX,INX>> - Increment the content of the X register by one
* <<INY,INY>> - Increment the content of the Y register by one
* <<INZ,INZ>> - Increment Z register
* <<LSR,LSR>> - Logical Shift Right - shift accumulator one bit to the right,
				shifting in zero in the highest bit
			
* <<NEG,NEG>> - negate AC, i.e. set AC to the 2s-complement of AC
* <<ORA,ORA>> - Bitwise OR accumulator with content of memory location
* <<RDL,RDL>> - Rotate Direct Left - similar to ROL, but do not shift in carry,
				but the highest bit of the original value
			
* <<RDL#,RDL#>> - Rotate Direct Left - similar to ROL, but do not shift in carry,
				but the highest bit of the original value
			
* <<RDR,RDR>> - Rotate Direct Right - similar to ROR, but do not shift in
				carry,
				but the lowest bit of the original value
			
* <<RDR#,RDR#>> - Rotate Direct Right - similar to ROR, but do not shift in
				carry,
				but the lowest bit of the original value
			
* <<ROL,ROL>> - Rotate Left - shift accumulator one bit to the left, shifting
				in
				the carry flag in bit 0, and shifting the
				highest bit into the
				carry flag instead.
			
* <<ROL#,ROL#>> - Rotate Left - shift accumulator one bit to the left, shifting
				in
				the carry flag in bit 0, and shifting the
				highest bit into the
				carry flag instead.
			
* <<ROR,ROR>> - Rotate Right - shift accumulator one bit to the right, shifting
				in the carry flag in the highest bit, and
				shifting
				bit 0 into the
				carry flag instead.
			
* <<ROR#,ROR#>> - Rotate Right - shift accumulator one bit to the right, shifting
				in the carry flag in the highest bit, and
				shifting
				bit 0 into the
				carry flag instead.
			
* <<SBC,SBC>> - Substract content of memory location from accumulator
* <<SBE,SBE>> - Subtract value from E register
* <<SBI,SBI>> - Subtract immediate value from a memory location
* <<SBQ,SBQ>> - Subtract immediate value from a register
* <<SUB,SUB>> - Subtract content of memory location from accumulator without
				using the carry flag as input
			
* <<SWP,SWP>> - swap upper and lower half of the operand
			

=== Bit Operations and Tests


* <<BBR#,BBR#>> - Branch on bit reset
* <<BBS#,BBS#>> - Branch on bit set
* <<BIT,BIT>> - Bitwise test with accumulator - AND the memory location with
				the
				accumulator, and set N (=bit 7), V (=bit 7), Z
				(iff all bits
				zero) flags from the result. In case of the accumulator addressing,
				simply
				set the flags from the
				accumulator
			
* <<RMB#,RMB#>> - Reset memory bit
* <<SMB#,SMB#>> - Set memory bit
* <<TMB#,TMB#>> - Test memory bit
* <<TRB,TRB>> - Test and Reset Bit - AND the memory location with the
				accumulator, and set the Z flag from the result, then
				CLEAR all bits
				in the
				memory location that are set in the accumulator.
			
* <<TSB,TSB>> - Test and Set Bit - AND the memory location with the
				accumulator,
				and set the Z flag from the result, then SET all
				bits in
				the
				memory location that are set in the accumulator.
			

=== Load/Store


* <<LDA,LDA>> - Load accumulator
* <<LDB,LDB>> - Load B with an immediate value
* <<LDE,LDE>> - Load E with an immediate value
* <<LDX,LDX>> - Load X register
* <<LDY,LDY>> - Load Y register
* <<LDZ,LDZ>> - Load Z register with a value
* <<LEA,LEA>> - Load Effective Address: compute the effective address and store
				it in the E (effective Address) register (always
				full width)
			
* <<STA,STA>> - Store the content of the accumulator into a memory location
			
* <<STI,STI>> - Store immediate byte value into a memory location
* <<STX,STX>> - Store the content of the X register to memory.
* <<STY,STY>> - Store the content of the Y register to memory.
* <<STZ,STZ>> - Store zero (or Z-register) into a memory location

=== Pushes/Pulls


* <<PHA,PHA>> - Push contents of the accumulator onto the stack
* <<PHB,PHB>> - Push B onto stack (full width)
* <<PHE,PHE>> - Push E onto stack (always full width)
* <<PHI,PHI>> - Push immediate value onto the stack
* <<PHM,PHM>> - Push contents of multiple registers onto the stack
* <<PHP,PHP>> - Push processor status register onto the stack
* <<PHX,PHX>> - Push contents of the X register onto the stack
* <<PHY,PHY>> - Push contents of the Y register onto the stack
* <<PHZ,PHZ>> - Push Z Register onto stack
* <<PLA,PLA>> - Pull the contents of the accumulator from the stack
* <<PLB,PLB>> - Pull B from stack (full width)
* <<PLE,PLE>> - Pull E from stack (full width)
* <<PLM,PLM>> - Pull contents of multiple registers from the stack
* <<PLP,PLP>> - Pull processor status register from the stack
* <<PLX,PLX>> - Pull the contents of the X register from the stack
* <<PLY,PLY>> - Pull the contents of the Y register from the stack
* <<PLZ,PLZ>> - Pull Z Register from stack
* <<PRB,PRB>> - Push and Replace Base register: Push base offset register to
				the
				stack, then transfer E-register to the base
				register
			

=== Transfers


* <<TAB,TAB>> - Transfer AC to B register
* <<TAX,TAX>> - Transfer the contents of accumulator into the X register
* <<TAY,TAY>> - Transfer the contents of accumulator into the Y register
* <<TAZ,TAZ>> - Transfer AC to Z Register
* <<TEA,TEA>> - Transfer E register to Accumulator
* <<TEB,TEB>> - Transfer E to B register (full width)
* <<TPA,TPA>> - Transfer Program counter to Accumulator
* <<TSX,TSX>> - Transfer the contents of the stack pointer into the X register
				(Note: needs RS to keep compatibility with 6502)
			
* <<TSY,TSY>> - Transfer stack pointer to Y
* <<TXA,TXA>> - Transfer the contents of the X register into the accumulator
			
* <<TXS,TXS>> - Transfer the contents of X register into the stack pointer
				(Note: needs RS to keep compatibility with 6502)
			
* <<TYA,TYA>> - Transfer the contents of the Y register into the accumulator
			
* <<TYS,TYS>> - Transfer Y to stack pointer
* <<TZA,TZA>> - Transfer Z Register to AC
* <<XAB,XAB>> - eXchange A register with B register. Always done full width, no
				flags set.
			
* <<XAX,XAX>> - eXchange AC with X register. Always done full width, no flags set.
			
* <<XAY,XAY>> - eXchange AC with Y register. Always done full width, no flags set.
			
* <<XYX,XYX>> - eXchange X with Y register. Always done full width, no flags set.
			
* <<XZX,XZX>> - eXchange X with Z register. Always done full width, no flags set.
			

=== Skip prefixes


* <<SCC,SCC>> - Skip on carry clear - skip next opcode when C flag is cleared
* <<SCS,SCS>> - Skip on carry set - skip next opcode when C flag is set
* <<SEQ,SEQ>> - Skip on equal - skip next opcode when Z flag is set
* <<SMI,SMI>> - Skip on minus - skip next opcode when N flag is set
* <<SNE,SNE>> - Skip on not equal - skip next opcode when Z flag is cleared
* <<SPL,SPL>> - Skip on plus - skip next opcode when N flag is cleared
* <<SVC,SVC>> - Skip on overflow clear - skip next opcode when V flag is cleared
* <<SVS,SVS>> - Skip on overflow set - skip next opcode when V flag is set

=== Flags


* <<CLC,CLC>> - Clear the C flag
* <<CLD,CLD>> - Clear the decimal (D) flag
* <<CLI,CLI>> - Clear the interrupt (I) flag
* <<CLV,CLV>> - Clear the overflow (V) flag
* <<NEC,NEC>> - Negate the carry flag
			
* <<SEC,SEC>> - Set the C flag
* <<SED,SED>> - Set the decimal (D) flag
* <<SEI,SEI>> - Set the interrupt (I) flag

=== System-oriented


* <<CSW,CSW>> - Compare and SWap - compare memory with AC, and if matches, set to value from XR. AC is loaded with the value from the memory location.
			

=== Others


* <<NOP,NOP>> - No operation

=== Description

 The BRK opcode is used to jump to the BRK vector. It pushes the return address and the status on the stack, then reads the BRK vector (doubling as IRQ vector) and jumps there.  Please note that the address put on the stack is the address of the next instruction. And the BRK opcode is using the immediate addressing mode (although the MOS manual does not state it). Thus the address put on the stack is two bytes behind the address of the BRK!  Before storing the status on the stack, the opcode sets the I-flag to avoid recursive calling of the interrupt routine.  When storing the status on the stack, the B-flag is set to indicate that the shared IRQ/BRK vector has been called from a BRK and not an IRQ.  Stack(SP--) &lt;= > NextPC Stack(SP--) &lt;= &lt; NextPC Stack(SP--) &lt;= Status \| B \| I PC &lt;= ($FFFE) 
=== 65k

 On the 65k, the RS prefix determines the size of the immediate operand, so that the return address that is pushed onto the stack depends on it.  As opposed to the IRQ, the BRK opcode stays in the user resp. hypervisor mode where it is executed.  In hypervisor mode, once the processor configuration register for abort vector table is set, the BRK vector is taken from the abort vector table. For details see the interrupt handling description.  In user mode the BRK always uses the standard two-byte $FFFE IRQ vector, sign-expanded to full address length.

=== Description

 Returns from an interrupt or a BRK opcode handling. It first pulls the status register from the stack, then takes the return address from the stack, increment it by one, and continue at the new address.  Status &lt;= Stack(++SP) -- bit 5=1 Tmp(0-7) &lt;= Stack(++SP) Tmp(8-15) &lt;= Stack(++SP) PC &lt;= Tmp; 
=== 65k

 The RTI prefix first reads the status from the current stack. If the "Not extended" flag is set (bit 5 is always 1 in the 6502 status register, so here it is used as "not extended" flag), then the normal handling as described above takes place.  If the "not extended" flag is clear, i.e. an extended stack frame is used:  Status &lt;= Stack(++SP) -- bit 5=0 ExtStatus &lt;= Stack(++SP) Tmp(0-7) &lt;= Stack(++SP) Tmp(8-15) &lt;= Stack(++SP) ... PC &lt;= Tmp;  Here the extended status byte is pulled from the stack after the standard status. In this extended status there are two bit that determine the size of the return address following on the stack. So the return address can be 16-, 32- or 64-bit. Note that the "00" designation (otherwise used for BYTE width) maps to the natural address width of the processor executing the code.  Also the user mode bit is stored in the extended stack frame. If the user mode bit is the same as the current mode, the execution continues in that mode. If the RTI code is executed in the supervisor mode, and the user mode bit is set, then the return address is interpreted as user mode address, and the execution continues in the user mode. If RTI is executed in user mode, and the user mode bit is clear (i.e. hypervisor mode), and ABORT sequence is triggered.  Note that the "natural" address width is taken from the target environment in case the process jumps from hypervisor to user mode.  If the operand is not wide enough as required for an address, it is sign-extended.

 Return from trap handling. Reads the extended status byte and the return address from hypervisor stack, then jumps to the return address.  &lt;Tmp &lt;= Stack(++SP) >Tmp &lt;= Stack(++SP) Tmp &lt;= Tmp+1 PC &lt;= Tmp; ExtStatus &lt;= Stack(++SP)

=== Description

 Trap into supervisor mode. Pushes the return address and the extended status byte on the hypervisor stack and jumps into hypervisor mode, using the appropriate trap vector. To return from the trap, the RTU operations is used. For compatibility with RTS, the return address minus one is stored on the stack.  Stack(SP--) &lt;= > NextPC-1 Stack(SP--) &lt;= &lt; NextPC-1 Stack(SP--) &lt;= ExtStatus PC &lt;= TrapVector(Operand) 
=== 65k

 The address put on the stack always has the natural width of the processor. Currently no further prefix is supported. The stack pointer used is that of the hypervisor stack.  This opcode can be used in user mode as well as in hypervisor mode. The extended status byte contains the user mode bit, so that the RTU opcode knows whether to return to user mode or hypervisor mode.  The extendend status byte also contains width bits that store the width of the return address on stack. BYTE is not used, but the real width is stored with the width bits.  Note for future expansions the RS prefix may extend the trap number (the immediate operand) to word, or even wider widths.
